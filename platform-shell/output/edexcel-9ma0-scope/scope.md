# UK Edexcel A level Mathematics: one-page resource scope

Checked 18 November 2026 against [Pearson’s 9MA0 specification](https://qualifications.pearson.com/content/dam/pdf/A%20Level/Mathematics/2017/specification-and-sample-assesment/a-level-l3-mathematics-specification-issue4.pdf), Issue 4, February 2020, linked from the current qualification page. This report is an implementation proposal, not an official Pearson scheme of work.

**Scope only:** no worksheets, app routes, database changes or production deployment have been created for this qualification.

## Recommended resource structure

Use **Kaizen A Level One-Pagers**, filtered to **Edexcel UK Mathematics (9MA0)**. Organise the action page into Pure Mathematics, Statistics and Mechanics, with compact topic groups and direct Student Pack / Teacher Pack / Teaching Tool links. Preserve the shared navigation. Both Pure exam papers can assess any Pure content: do not label the content menus as Paper 1 = Year 1 and Paper 2 = Year 2. Further Mathematics and International A Level are separate scopes.

The pack count is a Kaizen design proposal, not an official syllabus topic count. Broad clauses are split so eight questions remain readable on one A4 side. Each pack has a separate worked-solutions PDF and suggested marks. Include short procedural tasks, interpretation and reasoning; split a demanding topic rather than shrinking diagrams or cramming eight lengthy exam questions onto one page.

## Existing source strength

- Dedicated authored set: 7 clauses.
- Strong procedural source: 35 clauses.
- Adapt and supplement: 47 clauses.

A strong procedural source means a relevant generator exists, not that its mixed mode can be published without review. The mapping is based on repository tool definitions, activity descriptions and selected source inspections; it is not a numerical audit of every generator output. Every new paper still needs answer checking, diagrams, contextual reasoning and print review. The existing broad curriculum-alignment page is only a pilot, not a verified 9MA0 clause-level coverage claim.

## Work needing particular attention

- **Proof:** write deduction, exhaustion, counterexample and contradiction tasks; induction is not a substitute.
- **First principles:** polynomial coverage exists; sine/cosine proofs need dedicated writing.
- **Graphs:** author cobweb/staircase plots, derivative sketches, transformed graphs, scatter plots and motion graphs.
- **Statistics:** add coding/summary-square statistics, specified-rule outliers, correlation significance with supplied critical values or p-values, and binomial-to-normal approximation with continuity correction.
- **Official Large Data Set:** Kaizen’s present tool uses fictional training data. It can support general skills but must not be presented as Pearson LDS familiarity. Obtain the official data, verify variables/coding/context and reuse terms before reproducing extracts; link to the official source where appropriate. Do not invent weather observations and label them Pearson data.
- **Mechanics:** supply free-body diagrams, positive directions, assumptions, separate connected-body equations, vector motion and non-parallel moments. Keep eight questions sufficiently focused to fit.

## Scope boundaries

Exclude AP-only or Further-only activities such as L’Hospital’s Rule, MVT/EVT theorem exercises, arbitrary Taylor series, convergence tests, Euler’s method, polar calculus, cross-section solids and volumes of revolution, matrices, complex numbers and hyperbolic functions. Keep implicit/parametric differentiation to first derivatives. Exclude Poisson/geometric-distribution packs, general PDF calculus, confidence intervals, t-tests, and work/energy/momentum packs from this 9MA0 library. Retain binomial expected-count intuition where relevant to two-tailed tests. Use regression interpretation and calculator-supported correlation rather than requiring excluded coefficient formula calculations.

## Implementation sequence

1. **Three representative pilots:** quadratic/discriminant practice, a binomial hypothesis-test sheet and a resolving-forces sheet. This checks algebra, calculator statistics and diagram-heavy mechanics against the one-page constraint.
2. **Strong reusable families:** algebra, functions, coordinate geometry, sequences, differentiation/integration, core probability, binomial/normal calculations, SUVAT and friction. Select activity types and freeze original question sets.
3. **Dedicated reasoning and graphics:** proof, modelling, small-angle work, first-principles trig, log-linear models, graph interpretation, numerical-method failures, coding and correlation significance.
4. **Official LDS companions:** verify the official source and data reuse terms, then build familiarity/interpretation material; keep this distinct from fictional training data.
5. **Complete audit and publish readiness:** check every mapped clause and pack, mathematical answers, units/domains, diagrams, marking totals, exactly one student page, student/teacher separation, link integrity and responsive navigation. All claims remain topic-practice alignment, not official endorsement or exhaustive mock-exam coverage.

## Development complexity and reuse

The page, PDF layout, typography, permission footer, catalogue, stable links, mathematical rendering and much of the automated PDF QA can be reused from AP. Content selection and checking remain the main work. Pure algebra/calculus is relatively straightforward; multi-step mechanics and graphical interpretation require more layout/editorial work; proof and official LDS tasks require dedicated content. No new paid service or AI API is necessary for a static first edition. No authentication/payment/database changes are needed unless the owner separately changes access policy.

Proposed implementation files: `assets/site/alevel-maths.js`, `assets/site/alevel-maths.css`, `data/alevel-maths/edexcel-9ma0/`, `assets/alevel-maths/edexcel-9ma0/`, build/export/verification scripts and route/navigation tests. Refactor the AP print helpers into a shared module or carefully wrap them; do not change the existing AP packs unintentionally. Add the route and navigation entry in `app.js` / script includes in `index.html`, then regenerate shared-shell pages. These are proposed files, not changes made by this audit.
